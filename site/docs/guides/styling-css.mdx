---
title: Styling with plain CSS
description: Style the grid from a stylesheet with attribute selectors, or with classes passed to each part, and no build step.
---

Every part carries `data-grid-part`, its indexes and its state, so a stylesheet can style a grid
without a single class.

```css title="grid.css"
[data-grid-part="root"] {
    block-size: 24rem;
    border: 1px solid #d4d4d8;
    border-radius: 8px;
    font: 14px/1.4 system-ui, sans-serif;
}

/* opaque: the rows scroll under it (above them is the grid's own z-index) */
[data-grid-part="header"] {
    background: #fafafa;
}

[data-grid-part="header-cell"],
[data-grid-part="cell"] {
    display: flex;
    align-items: center;
    padding-inline: 12px;
    border-inline-end: 1px solid #e4e4e7;
}

[data-grid-part="row"] {
    border-block-end: 1px solid #e4e4e7;
}

[data-grid-part="cell"]:focus-visible,
[data-grid-part="cell"][data-active] {
    outline: 2px solid #2563eb;
    outline-offset: -2px;
}
```

## Clean edges at any zoom

At a zoom or a device pixel ratio that puts the viewport's edge between two device pixels (a
browser zoom of 90% or 110%, a screen scaled to 125%), the browser draws the cells that scroll
into the device pixel at the edge but snaps a sticky part's background to whole pixels. That
pixel then shows the cells passing under the header, a pinned column or the bottom summary rows:
a row of dots along the edge while it scrolls. Paint those parts a few pixels past the edge, in
their own background, and the viewport clips the rest:

```css title="grid-edges.css"
/* one surface under the frame's rounded corners (cuts nothing) */
[data-grid-part="grid"] {
    clip-path: inset(0);
}

[data-grid-part="header"]::before,
[data-grid-part="header-row"]:first-child::before,
[data-grid-part="summary"][data-summary="bottom"]::before,
[data-pinned="start"][data-column-index="0"]::before,
[data-pinned="end"]:not(:has(~ [data-pinned="end"]))::before {
    content: "";
    position: absolute;
    background: inherit;
    pointer-events: none;
}

[data-grid-part="header"]::before,
[data-grid-part="header-row"]:first-child::before {
    inset-inline: 0;
    top: -3px;
    height: 3px;
}

[data-grid-part="summary"][data-summary="bottom"]::before {
    inset-inline: 0;
    bottom: -3px;
    height: 3px;
}

[data-pinned="start"][data-column-index="0"]::before {
    inset-block: 0;
    inset-inline-start: -3px;
    width: 3px;
}

[data-pinned="end"]:not(:has(~ [data-pinned="end"]))::before {
    inset-block: 0;
    inset-inline-end: -3px;
    width: 3px;
}

/* a cell cuts its content a few pixels out, so its own clip leaves the cover alone */
[data-grid-part="cell"][data-pinned="start"][data-column-index="0"],
[data-grid-part="cell"][data-pinned="end"]:not(:has(~ [data-pinned="end"])) {
    overflow: clip;
    overflow-clip-margin: 3px;
}
```

The examples share this stylesheet (`examples/shared/src/styles/grid-edges.css`). It needs the
parts' backgrounds opaque, as the header's above.

## Several grids on a page

Scope the selectors under a class on the root (`.people [data-grid-part="cell"]`), or pass a
class to each part with `className`.

## What not to override

The parts' positions and sizes are inline and win over your stylesheet's `position`, `top`,
`left`, `width` and `height`. Pad a cell, border it, color it: its box stays where the engine
puts it.

## Further

Classes can depend on anything: a part's state, its column, its row's data. The
[`styling-showcase`](/examples/styling-showcase) example restyles one grid three ways from class
maps alone.
