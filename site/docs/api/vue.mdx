`@fragiola/data-grid-vue` has every primitive of the React package, as a Vue 3.5 component, and
every hook as a composable, over the same core (re-exported whole). The behaviour, the `data-*`
attributes, the ARIA and the structural style of every element are the same: the other pages of
these docs describe each part, and this page says how its React API is written in Vue.

```ts
import {
    typedDataGrid,
    useDataGrid,
    useDataGridRef,
    useRowWindow,
    type Column,
} from "@fragiola/data-grid-vue";
import type { VNodeChild } from "vue";
```

## Typing by your row

A React part takes the row type as a type argument (`<DataGrid.Rows<Person>>`, or inferred from
`Root`'s `rows`); a Vue template cannot pass one. `typedDataGrid<Person>()` returns the same
components, typed by `Person`: the `row` of a slot, a cell's `row` and the columns `Root` takes
are then of your row type.

```vue title="people-grid.vue"
<script setup lang="ts">
import { type Column, typedDataGrid } from "@fragiola/data-grid-vue";
import type { VNodeChild } from "vue";

interface Person {
    id: number;
    name: string;
}

const DataGrid = typedDataGrid<Person>();
const columns: Column<Person, VNodeChild>[] = [{ key: "name", name: "Name", width: 180 }];
defineProps<{ people: Person[] }>();
</script>

<template>
    <DataGrid.Root :columns="columns" :rows="people" :row-key="(row) => row.id" style="height: 400px">
        <DataGrid.Grid aria-label="People">
            <DataGrid.Header />
            <DataGrid.Body />
        </DataGrid.Grid>
    </DataGrid.Root>
</template>
```

A grid that installs [features](/docs/concepts/features) passes them too:
`typedDataGrid<Person, typeof features>()` types `Root` by their props. Declare the list
`as const`, once, in `setup`.

```vue title="people-grid.vue"
<script setup lang="ts">
import { typedDataGrid } from "@fragiola/data-grid-vue";
import { navigation } from "@fragiola/data-grid-vue/navigation";
import { sorting } from "@fragiola/data-grid-vue/sorting";

const features = [navigation(), sorting()] as const;
const DataGrid = typedDataGrid<Person, typeof features>();
</script>

<template>
    <DataGrid.Root :features="features" :columns="columns" :rows="people">
        <!-- … -->
    </DataGrid.Root>
</template>
```

| export | description |
| --- | --- |
| `typedDataGrid<TRow, TFeatures>()` | the `DataGrid` components typed by the row type `TRow` and the installed features (none when left out), as a `TypedDataGrid<TRow, TFeatures>` (the same objects as `DataGrid`); Vue only |
| `DataGrid` | the components, with the row type erased: enough for a part that never reads the row type |

## How React's props map

| React | Vue |
| --- | --- |
| `render={<table />}` | `as="table"` (a tag or a component) |
| `render={(props, state) => …}` | the `render` scoped slot, `#render="{ props, state, children }"`: bind `v-bind="props"` on your element and render `<component :is="children" />` inside it |
| `className`, `style` | the `class` and `style` attributes, merged under the structural style (structural keys win; the layers and the pinned cells drop the keys the engine writes, as in React) |
| `className={(state) => …}`, `style={(state) => …}` | no function form: a `data-*` selector (`data-active:outline-2`), or the `render` slot's `state` |
| `onKeyDown`, `onClick`, `onPointerDown`, `onCopy`, `onPaste`, … | listeners (`@keydown`, `@click`, `@pointerdown`, `@copy`, `@paste`): the part's own first, then yours, then the grid's keys, clicks, presses and clipboard on `Root`, so `preventDefault` in yours cancels the grid's |
| `onEditingCellChange` and the other `Root` callbacks | the same props, `:on-editing-cell-change="…"`, or the listener form `@editing-cell-change="…"` |
| `features={features}` | `:features="features"`, fixed when the grid is created |
| a feature's props (`sortColumns`, `activePosition`, `rowSelection`, `selectedRange`, `onRangePaste`, `onFill`, …) | attributes on `Root`: `:sort-columns`, `@sort-columns-change`, `:active-position`, `@active-position-change`, `:on-fill` (or camelCase), typed by `typedDataGrid<TRow, typeof features>()` |
| `ref` | a template ref on a part is its component instance; the element is its `$el`. A handle on the grid is a `gridRef` |
| children functions (`Rows`, `Cells`, `HeaderRows`, `HeaderCells`, `SummaryRows`, `SummaryCells`) | the default scoped slot: `v-slot="{ row }"` or `v-slot="{ cell }"` |
| `Cell` children | the default slot, `v-slot="{ cell, state }"`; `Row`, `HeaderCell`, `SummaryRow`, `SummaryCell` and `RowDetail` give `{ state }` |
| `renderCell`, `renderHeaderCell` and the other column renderers | the same, returning vnodes: columns are `Column<TRow, VNodeChild>` (`renderCell: ({ row }) => h("b", row.name)`) |
| `<DataGrid.Rows<Person>>` and the other type arguments | `typedDataGrid<Person>().Rows` |

A number in the structural style is written with its unit (`px`): Vue, unlike React, adds none.

## Components

Every part is `DataGrid.<Part>`, with the props of its React counterpart except `render`,
`className`, `style`, `ref` and `children` (see the table above). Each accepts `as` and the
`render` slot, except the collection parts, which render no element of their own.

| part | Vue props | slots |
| --- | --- | --- |
| `DataGrid.Root` | the core's root props (`GridRootProps`: `columns`, `rows` or `rowCount` + `getRow`, `rowKey`, the sizes, every piece of state controlled or not, its callbacks, the engine's options), `gridRef`, `features`; an installed feature's props as attributes | default |
| `DataGrid.Grid` | none | default |
| `DataGrid.Header` | none | default |
| `DataGrid.HeaderRows` | none | default `{ row }` |
| `DataGrid.HeaderRow` | `row` | default |
| `DataGrid.HeaderCells` | none | default `{ cell }` |
| `DataGrid.HeaderCell` | `cell` | default `{ state }` |
| `DataGrid.Body` | none | default |
| `DataGrid.Rows` | none | default `{ row }` |
| `DataGrid.Row` | `row` | default `{ state }` |
| `DataGrid.Cells` | none | default `{ cell }` |
| `DataGrid.Cell` | `cell` | default `{ cell, state }` |
| `DataGrid.RowDetail` | none | default `{ state }` |
| `DataGrid.Empty` | none | default |
| `DataGrid.Summary` | `position` | default |
| `DataGrid.SummaryRows` | `position` | default `{ row }` |
| `DataGrid.SummaryRow` | `row` | default `{ state }` |
| `DataGrid.SummaryCells` | none | default `{ cell }` |
| `DataGrid.SummaryCell` | `cell` | default `{ state }` |

```vue title="people-grid.vue"
<DataGrid.Grid as="table" aria-label="People">
    <DataGrid.Body as="tbody">
        <DataGrid.Rows v-slot="{ row }">
            <DataGrid.Row :row="row" as="tr">
                <DataGrid.Cells v-slot="{ cell }">
                    <DataGrid.Cell :cell="cell">
                        <template #render="{ props, state, children }">
                            <td v-bind="props" :title="state.active ? 'active' : undefined">
                                <component :is="children" />
                            </td>
                        </template>
                    </DataGrid.Cell>
                </DataGrid.Cells>
            </DataGrid.Row>
        </DataGrid.Rows>
    </DataGrid.Body>
</DataGrid.Grid>
```

Scrolling renders nothing until the rendered window changes: the engine writes the layers'
offsets itself, and Vue never patches them.

## Composables

The hooks of the React package, as composables. Call them in `setup`. A part composable takes its
row or cell (a value, a ref or a getter) and returns `{ state, props }` as computed refs
(`PartComposableResult`): bind `v-bind="props.value"` on your element, the structural style in
`props.value.style`, its listeners Vue's (`onPointerdown`, `onKeydown`).

| composable | returns |
| --- | --- |
| `useDataGrid()` | `{ model, engine }` of the enclosing `Root` (plain values); with a `gridRef`, a shallow ref of them, `null` until a root holds it. `useDataGrid<Person, typeof features>()` types the features' keys |
| `useDataGridRef()`, `createDataGridRef()` | a handle on a grid for `<DataGrid.Root :grid-ref="gridRef">`: the same object for the component's life; `createDataGridRef` outside a component. Both take the features after the row type |
| `useRowWindow(gridRef?)`, `useColumnWindow(gridRef?)` | the rows or the columns in view and rendered (`AxisWindow`), as a shallow ref |
| `useGridView()` | the grid's view, as a shallow ref |
| `useRows()`, `useCells(row)` | the rendered rows, a row's rendered cells, as computed refs |
| `useHeaderRows()`, `useHeaderCells(row?)` | the header rows, a header row's cells |
| `useSummaryRows(position?)`, `useSummaryCells(row?)` | the summary rows, a summary row's cells |
| `useRow(row)`, `useCell(cell)`, `useHeaderCell(cell)`, `useSummaryRow(row)`, `useSummaryCell(cell)`, `useRowDetail(row)` | a part's `{ state, props }` |
| `useColumnResizer(cell)`, `useRowDragHandle(row)`, `useGroupToggle(row)`, `useGroupLabel(cell)` | the `{ state, props }` of an element of yours: a resize handle, a drag handle, a group's toggle, a sticky group label |
| `useCellEdit(cell)` | the editor props of the cell being edited (`EditCellRenderProps`), a computed ref, `null` otherwise |

The opt-in entry points have the same exports as React's:

| entry | composable |
| --- | --- |
| `@fragiola/data-grid-vue/local` | `useLocalRows(rows, columns, options?)`: rows in memory, sorted, filtered, searched, grouped and paged. Bind `v-bind="local.props"` on `Root`; each field is a getter, read when used; its sort needs `sorting()` in `:features` |
| `@fragiola/data-grid-vue/sorting` | `sorting()`, the [sorting feature](/docs/concepts/sorting), and `sortColumnsOf(view)`, `headerCellSort`, `SortColumn` (the core's, re-exported) |
| `@fragiola/data-grid-vue/navigation` | `navigation()`, the [keys and the active cell](/docs/concepts/keyboard), and `samePosition` |
| `@fragiola/data-grid-vue/row-selection` | `rowSelection()`, the [row selection](/docs/concepts/row-selection), its helpers (`selectionStatus`, `withRowKeys`, …), and `useSelectAll(rowKeys, gridRef?)`: a "select all" control's state and its `toggle`, each field a getter |
| `@fragiola/data-grid-vue/range` | `cellRange()`, [ranges of cells](/docs/concepts/cell-selection) (with `navigation()`), `keptRange`, `sameCellRange` |
| `@fragiola/data-grid-vue/clipboard` | `clipboard()` (with `cellRange()`), `parseTsv`, `toTsv`, `pastedRange`, `rangeText` |
| `@fragiola/data-grid-vue/fill` | `fillHandle()`, the [fill handle](/docs/concepts/fill) (with `cellRange()`), `repeatedFill`, and `useFillHandle(cell)`: the `{ state, props }` of your handle |

## Types

Each part exports its props and its slots, named as in React: `RootProps`, `RootSlots`,
`RootState`, `GridProps`, `GridSlots`, `HeaderProps`, `HeaderSlots`, `HeaderRowsProps`,
`HeaderRowsSlots`, `HeaderRowProps`, `HeaderRowSlots`, `HeaderCellsProps`, `HeaderCellsSlots`,
`HeaderCellProps`, `HeaderCellSlots`, `BodyProps`, `BodySlots`, `RowsProps`, `RowsSlots`,
`RowProps`, `RowSlots`, `CellsProps`, `CellsSlots`, `CellProps`, `CellSlots`, `RowDetailProps`,
`RowDetailSlots`, `EmptyProps`, `EmptySlots`, `SummaryProps`, `SummarySlots`,
`SummaryRowsProps`, `SummaryRowsSlots`, `SummaryRowProps`, `SummaryRowSlots`,
`SummaryCellsProps`, `SummaryCellsSlots`, `SummaryCellProps`, `SummaryCellSlots`.

| type | description |
| --- | --- |
| `DataGridComponent<Props, Slots>` | a part's component type: its props, plus any fallthrough attribute, and its scoped slots |
| `TypedDataGrid<TRow, TFeatures>` | what `typedDataGrid<TRow, TFeatures>()` returns: every part typed by `TRow`, `Root` by the features' props too |
| `PrimitiveProps` | what every part accepts: `as` |
| `AsProp` | a tag name or a component |
| `RenderSlot<State>` | the `render` slot every part accepts |
| `RenderSlotProps<State>` | what it receives: `props`, `state`, `children` |
| `SlotFunction<Scope>` | a scoped slot: its scope in, the nodes it renders out |
| `PartComposableResult<State>` | what a part composable returns: `state` and `props`, computed refs |

React's `DivPrimitiveProps`, `PrimitiveProps` (its own: `render`, `className`, `style`),
`RenderedProps` and `RenderProp` have no Vue counterpart: the slots and attributes above replace
them.

## Server rendering

Not supported yet in Vue: the Vue package renders in the browser. The React package's
[server rendering](/docs/guides/server-rendering) has no Vue counterpart today.
