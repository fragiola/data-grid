`@fragiola/data-grid-angular` has every primitive of the React package, as an Angular 22
attribute directive on your own element, and every hook as an injection function, over the same
core (re-exported whole). The behaviour, the `data-*` attributes, the ARIA and the structural
style of every element are the same: the other pages of these docs describe each part, and this
page says how its React API is written in Angular.

```ts
import {
    DATA_GRID,
    createDataGridRef,
    injectDataGrid,
    injectRowWindow,
    templateContent,
    type Column,
    type DataGridNode,
} from "@fragiola/data-grid-angular";
```

The directives are standalone: import `DATA_GRID` (every directive) in a component. They are
zoneless and `OnPush`-safe: the grid's view is a signal fed by the engine, and scrolling within
the rendered window changes no signal at all.

## Your elements, your templates

A React part renders an element, `render` swaps it. In Angular the element is always yours: the
directive goes on it (a `div`, a `tr`, a `td`, a component's host), and the recursion is your
templates: `<ng-template dataGridRows let-row>` repeats its content for each rendered row, as
React's children function does. There is no default content: write the rows and cells out.

```ts title="people-grid.ts"
import { ChangeDetectionStrategy, Component, input } from "@angular/core";
import { type Column, DATA_GRID, type DataGridNode } from "@fragiola/data-grid-angular";

interface Person {
    id: number;
    name: string;
}

@Component({
    selector: "app-people-grid",
    imports: [DATA_GRID],
    changeDetection: ChangeDetectionStrategy.OnPush,
    template: `
        <div dataGridRoot [columns]="columns" [rows]="people()" [rowKey]="rowKey" style="height: 400px">
            <div dataGridGrid aria-label="People">
                <div *dataGridHeader class="bg-white">
                    <div dataGridHeaderRow>
                        <ng-template [dataGridHeaderCells]="columns" let-cell>
                            <div [dataGridHeaderCell]="cell"><ng-container *dataGridCellContent /></div>
                        </ng-template>
                    </div>
                </div>
                <div dataGridBody>
                    <ng-template [dataGridRows]="columns" let-row>
                        <div [dataGridRow]="row" class="border-b">
                            <ng-template [dataGridCells]="columns" let-cell>
                                <div [dataGridCell]="cell" class="px-3 data-active:outline-2">
                                    <ng-container *dataGridCellContent />
                                </div>
                            </ng-template>
                        </div>
                    </ng-template>
                </div>
            </div>
        </div>
    `,
})
export class PeopleGrid {
    readonly people = input.required<Person[]>();
    readonly columns: Column<Person, DataGridNode>[] = [{ key: "name", name: "Name", width: 180 }];
    readonly rowKey = (row: Person) => row.id;
}
```

A part that renders only sometimes is a **structural directive** on its element:
`*dataGridHeader` (none without a header row), `*dataGridEmpty` (only while there are no rows),
`*dataGridRowDetail` (only while its row is expanded), `*dataGridSummary="'top'"` (only while
there are summary rows there), and the elements of yours React gives through a hook:
`*dataGridColumnResizer`, `*dataGridGroupToggle`, `*dataGridFillHandle`, `*dataGridCellEdit`.

## Typing by your row

The root infers your row type from its `columns` and `rows`. A template's context is typed by
what you give its directive: the columns (`[dataGridRows]="columns"`) or the root
(`#grid="dataGridRoot"`, then `[dataGridRows]="grid"`); without either, the row is `unknown`.
Columns are the core's `Column<TRow, DataGridNode>`.

## Column renderers

A column's renderers (`renderCell`, `renderHeaderCell`, `renderGroupCell`, `renderSummaryCell`,
`renderEditCell`) return a `DataGridNode`: text (a string or a number), nothing, or a template with
its context, `templateContent(template, context)`. `*dataGridCellContent` renders the default
content of the cell it is in, the renderer's template included. `[dataGridTemplate]` types the
template's variables by its context.

```ts title="people-grid.ts"
@Component({
    imports: [DATA_GRID],
    template: `
        <ng-template #nameCell [dataGridTemplate]="nameContext" let-row="row">
            <b>{{ row.name }}</b>
        </ng-template>
        <!-- the grid, its cells rendering <ng-container *dataGridCellContent /> -->
    `,
})
export class PeopleGrid {
    readonly nameContext = contextOf<CellTemplateProps<Person>>();
    readonly nameCell = viewChild.required<TemplateRef<TemplateContext<CellTemplateProps<Person>>>>("nameCell");
    readonly columns: Column<Person, DataGridNode>[] = [
        { key: "name", name: "Name", width: 180, renderCell: (props) => templateContent(this.nameCell(), props) },
    ];
}
```

The template renders with the props the renderer was given, as its `$implicit` too
(`let-props`); a new context for the same template updates its view in place.

## How React's props map

| React | Angular |
| --- | --- |
| `<DataGrid.X>` | the directive `[dataGridX]` on your element (`DataGridX`): `DataGrid.Root` is `dataGridRoot`, `DataGrid.Cell` is `[dataGridCell]="cell"` |
| `render={<table />}`, `render={(props, state) => …}` | your own element: `<table dataGridGrid>`, `<td [dataGridCell]="cell">` |
| children functions (`Rows`, `Cells`, `HeaderRows`, `HeaderCells`, `SummaryRows`, `SummaryCells`) | a template: `<ng-template dataGridRows let-row>`, `<ng-template dataGridCells let-cell>` |
| a part's default children (a cell's renderer or value) | `<ng-container *dataGridCellContent />` inside the part |
| `className`, `style` | your element's `class` and `style`, under the structural style (structural keys win; the layers and the pinned cells drop the keys the engine writes from your static style; never bind those keys yourself) |
| `className={(state) => …}` | a `data-*` selector (`data-active:outline-2`), or the part's state: `#cell="dataGridCell"`, then `[class.active]="cell.state()?.active"` |
| `onKeyDown`, `onClick`, `onPointerDown`, `onCopy`, `onPaste`, … | your listeners (`(keydown)`, `(click)`, …): yours first, then the grid's keys, clicks, presses and clipboard on the root, so `preventDefault` in yours cancels the grid's |
| `Root`'s `onXChange` and the other callbacks | outputs without `on`: `(activePositionChange)`, `(sortColumnsChange)`, `(cellEdit)`, `(rangePaste)`, `(rowWindowChange)`, `(rowsEndReached)`, …; `[(activePosition)]` binds both ways |
| `onRowMove`, `onFill` (given, the feature is on) | the inputs `reorderableRows` and `fillable` turn it on; the outputs `(rowMove)` and `(fill)` tell |
| `onBeforeRangePaste` | the input `[beforeRangePaste]` (a function: `false` refuses) |
| `ref` | your element's own template reference; a handle on the grid is a `gridRef` (`createDataGridRef()`) |
| `useX(…)` hooks | `injectX(…)` injection functions (below) |
| `<DataGrid.Rows<Person>>` and the other type arguments | `[dataGridRows]="columns"` (or the root) |
| `useColumnResizer`, `useRowDragHandle`, `useGroupToggle`, `useGroupLabel`, `useFillHandle`, `useCellEdit` on your element | the directives `*dataGridColumnResizer="cell"`, `[dataGridRowDragHandle]="row"`, `*dataGridGroupToggle="row"`, `[dataGridGroupLabel]="cell"`, `*dataGridFillHandle="cell"`, `*dataGridCellEdit="let edit"` |

A part's `state()` is `undefined` on the first pass of a binding on its own element (Angular
evaluates class bindings before the element's inputs), so read it with `?.`.

## Directives

| directive | inputs | template context |
| --- | --- | --- |
| `[dataGridRoot]` | the core's root props (`GridRootProps`: `columns`, `rows` or `rowCount` + `getRow`, `rowKey`, the sizes, every piece of state controlled or not, the engine's options), `reorderableRows`, `fillable`, `beforeRangePaste`, `gridRef`; the callbacks are outputs | |
| `[dataGridGrid]` | none | |
| `*dataGridHeader` | none | |
| `ng-template[dataGridHeaderRows]` | what types it (optional) | `{ $implicit: row, row }` |
| `[dataGridHeaderRow]` | its header row (optional: the columns' row) | |
| `ng-template[dataGridHeaderCells]` | what types it (optional) | `{ $implicit: cell, cell }` |
| `[dataGridHeaderCell]` | its cell | |
| `[dataGridBody]` | none | |
| `ng-template[dataGridRows]` | what types it (optional) | `{ $implicit: row, row }` |
| `[dataGridRow]` | its row | |
| `ng-template[dataGridCells]` | what types it (optional) | `{ $implicit: cell, cell }` |
| `[dataGridCell]` | its cell | |
| `*dataGridCellContent` | none: the cell it is in | |
| `*dataGridRowDetail` | none: the row it is in | `{ $implicit: state, state }` |
| `*dataGridEmpty` | none | |
| `*dataGridSummary` | its position | `{ $implicit: state, state }` |
| `ng-template[dataGridSummaryRows]` | its position (optional: the summary's) | `{ $implicit: row, row }` |
| `[dataGridSummaryRow]` | its row | |
| `ng-template[dataGridSummaryCells]` | what types it (optional) | `{ $implicit: cell, cell }` |
| `[dataGridSummaryCell]` | its cell | |
| `*dataGridColumnResizer`, `*dataGridGroupToggle`, `*dataGridFillHandle` | a header cell, a row (or cell), a cell | `{ $implicit: state, state }` |
| `[dataGridRowDragHandle]`, `[dataGridGroupLabel]` | a row (or cell), a group's header cell | |
| `*dataGridCellEdit` | its cell (optional: the cell it is in) | `{ $implicit: edit, edit }` |
| `[dataGridTemplate]` | a context type (`contextOf<…>()`) | that context |
| `[dataGridBind]` | an injection function's `props()` | |

Each attribute directive is exported as its name (`#row="dataGridRow"`) and has a `state()`
signal. Scrolling renders nothing until the rendered window changes: the engine writes the
layers' offsets itself, and Angular never writes them.

## Injection functions

The hooks of the React package, as injection functions: call them in an injection context (a
constructor or a field). A part's takes its row or cell (a value, a signal or a getter) and
returns `{ state, props }` as signals (`PartInjectResult`); put `props()` on your element with
`[dataGridBind]`.

| function | returns |
| --- | --- |
| `injectDataGrid()` | `{ model, engine }` of the root around (read them once its inputs are set: in a listener, an effect, `ngOnInit`); with a `gridRef`, a signal of them, `null` until a root holds it |
| `createDataGridRef()` | a handle on a grid for `<div dataGridRoot [gridRef]="gridRef">` (React's `useDataGridRef` and `createDataGridRef`) |
| `injectRowWindow(gridRef?)`, `injectColumnWindow(gridRef?)` | the rows or the columns in view and rendered (`AxisWindow`), as a signal |
| `injectGridView()` | the grid's view, as a signal |
| `injectRows()`, `injectCells(row)` | the rendered rows, a row's rendered cells |
| `injectHeaderRows()`, `injectHeaderCells(row?)` | the header rows, a header row's cells |
| `injectSummaryRows(position?)`, `injectSummaryCells(row?)` | the summary rows, a summary row's cells |
| `injectRow(row)`, `injectCell(cell)`, `injectHeaderCell(cell)`, `injectSummaryRow(row)`, `injectSummaryCell(cell)`, `injectRowDetail(row)` | a part's `{ state, props }` |
| `injectColumnResizer(cell)`, `injectRowDragHandle(row)`, `injectGroupToggle(row)`, `injectGroupLabel(cell)`, `injectFillHandle(cell)` | the `{ state, props }` of an element of yours (the directives above are the shorter form; a measured row and a group label need theirs: the engine reads their element) |
| `injectCellEdit(cell)` | the editor props of the cell being edited (`EditCellRenderProps`), `null` otherwise |

The opt-in entry points:

| entry | exports |
| --- | --- |
| `@fragiola/data-grid-angular/local` | `injectLocalRows(rows, columns, options?)`: rows in memory, sorted, filtered, searched, grouped and paged, each field a getter; `[dataGridLocalRows]="local"` on the root gives it their props (React's `{...local.props}`) |
| `@fragiola/data-grid-angular/selection` | `injectSelectAll(rowKeys, gridRef?)`: a "select all" control's state and its `toggle`, each field a getter |

## Types

| type | description |
| --- | --- |
| `DataGridNode` | what a column's renderers return: text, nothing, or a `TemplateContent` |
| `TemplateContent<C>`, `TemplateContext<C>` | a template with its context; the context a template renders with (`C` and its `$implicit`) |
| `ContextOf<C>` | a context type for `[dataGridTemplate]` (`contextOf<C>()`) |
| `CellTemplateProps<TRow>` | a body cell's render props (`renderCell`'s) |
| `RowsContext`, `CellsContext`, `HeaderRowsContext`, `HeaderCellsContext`, `SummaryRowsContext`, `SummaryCellsContext` | the collection templates' contexts |
| `RowDetailContext`, `SummaryTemplateContext`, `ColumnResizerContext`, `GroupToggleContext`, `FillHandleContext`, `CellEditContext` | the structural parts' contexts |
| `RowInfo`, `CellInfo`, `HeaderRowInfo`, `HeaderCellInfo`, `SummaryRowInfo`, `SummaryCellInfo` | what the templates hand you, as in React |
| `DataGridContextValue`, `DataGridRef` | the model and the engine; the handle on a grid |
| `PartInjectResult<State>`, `ValueOrSignal<T>` | what a part's injection function returns; what it takes |

React's `<Part>Props`, `DivPrimitiveProps`, `PrimitiveProps`, `RenderedProps` and `RenderProp`
have no Angular counterpart: a directive's inputs and your own element replace them.

## Server rendering

Not supported yet in Angular: the Angular package renders in the browser. The React package's
[server rendering](/docs/guides/server-rendering) has no Angular counterpart today.
